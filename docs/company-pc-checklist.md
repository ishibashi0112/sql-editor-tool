# 会社 PC での確認のチェックリスト（0.7.0）

`sql-editor-tool-0.7.0.vsix` を会社 PC の VS Code に入れて確かめるためのものです。会社 PC で確認済みなのは 0.1.0（接続・表示・絞り込み・中止）と 0.2.0（画面ですぐ絞り込む）だけで、0.3.0〜0.7.0 の機能はまだ確かめていません。結果は `docs/handover.md` の §14 に記録します。

## 確かめるときのポイント

優先度は ★★（実機でしか分からない。必ず見る）、★（できれば見る）、無印（時間があれば）の 3 段階です。

| 機能 | 版 | これまでに確かめたところ | 実機でしか分からないこと |
|---|---|---|---|
| 入力補完 | 0.7.0 | 単体テストだけ（VS Code の中では一度も動かしていない） | ★★ 補完が出るか、ステータスバーでの接続の選択、出るまでの時間 |
| 列の設定（yyyymmdd を日付に、キーの指定、案内） | 0.6.0 | ブラウザの開発用ページ、Docker の SQL Server・Oracle | ★★ 案内の候補が正しいか、日付の絞り込みの件数が A5 と合うか、VS Code を閉じても設定が残るか |
| Oracle のドライバ | 0.1.0〜0.6.0 | Docker の Oracle 23ai（AL32UTF8） | ★★ 社内の 19c・JA16SJIS に Thin モードでつながるか（O-02）、中止の直後の再実行、CHAR 列 |
| レポートの入力欄の種類の推定 | 0.5.0 | Docker の SQL Server 2022 | ★★ 社内の 2012 SP2 でも同じ種類になるか（O-15） |
| レポートの選択肢・相対の日付 | 0.5.0 | ブラウザの開発用ページ | ★★ 選択肢を日本語入力で絞れるか、VS Code を開き直したときの既定値 |
| レポートの基本（作る・開く・一覧・実行） | 0.4.0 | Mac の拡張開発ホスト（デモ接続） | ★ 実 DB で件数が A5 と合うか |
| テーブル検索 | 0.3.0 | Mac の拡張開発ホスト（デモ接続） | ★ テーブルの数が多いときの速さ |

## 持ち帰るもの

- 各項目の ○ / × と、気づいたこと。
- 件数、所要時間（体感でよい）、エラーの番号とメッセージ。
- 期待と違ったときは、SQL の形（`列 >= :名前` など）と列の型。

ホスト名・IP・DB 名・スキーマ名・テーブル名・列名・業務データは伏せてください（「日付の列 A」のように置き換える）。

### D-2 入力欄の種類の推定（0.5.0、O-15）

次の形の SQL を 1 本作ってください（実際の列に置き換える）。

```sql
SELECT *
FROM <テーブル>
WHERE <yyyymmdd の列> >= :開始日
  AND <yyyymmdd の列> <= :終了日
  AND (:コード IS NULL OR <文字列のコードの列> = :コード)
  AND <数値の列> >= :最小数量
  AND <datetime の列> >= :登録日
```

| No | 優先 | 操作 | 期待する結果 | 結果 |
|---|---|---|---|---|
| D-2-1 | ★★ | 開いて「⚙ 入力欄」を開く | 開始日・終了日＝日付（yyyymmdd の文字列の列と比べる）、コード＝文字列、最小数量＝数値、登録日＝日付（日付型の列と比べる）。どれにも「（推定）」が付く | |
| D-2-2 | ★ | `AND <列> = COALESCE(:別名, <列>)` を 1 行足す | ほかの欄の種類が崩れない（別名は文字列） | |
| D-2-3 | ★ | 「⚙ 入力欄」で保存 → `.sql` の先頭のコメントを見る | 推定した種類が書かれ、「（推定）」は消える | |

期待と違った欄があれば、その行の形と列の型を控えてください。
